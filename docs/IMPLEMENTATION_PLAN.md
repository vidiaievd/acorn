# План имплементации: Волшебный мир (ACORN), Unity 3D

Этапы из [GAME_DESIGN.md](GAME_DESIGN.md), разбитые на маленькие шаги. Каждый этап добавляет **одну новую вещь** и заканчивается демо, в которое можно поиграть. Один шаг — одна логическая задача: один стикер на доске и обычно один коммит.

**Порядок:** карта и стандартный герой → наш герой → магия → зверь-спутник → превращение → второй герой → жители и монеты → кристаллы суперсил → враги → новые формы → кастомизация → загадки → босс → времена года → остальные боссы → меню и сохранения → релиз.

## Как читать таблицы

**ID:** `E<этап>.<шаг>`, например `E3.4`. Используем в названиях веток и коммитов: `E3.4: синий кристалл маны`.

**Кто:**
- 👨 **Папа:** архитектура, сложный код, Git, настройка Unity.
- 🧒 **Старший** (11): скрипты, Visual Scripting, сборка уровней, настройка эффектов.
- 👧 **Младший** (9): концепты, цвета, раскраска карты, звуки, имена, тестирование.
- 👪 **Все:** делаем вместе.

Роли — только подсказка. Пусть дети пробуют всё.

**Модель Claude** (какую выбрать для помощи с шагом):

| Модель | Когда брать |
|---|---|
| **Opus 5.5** | Архитектура, связки систем, превращение, шейдеры, ИИ босса, сохранения, непонятные баги |
| **Sonnet 5.5** | Обычные фичи: префаб со скриптом, UI, эффекты, интеграция пакета |
| **Haiku 5.5** | Мелочи: новые данные (ScriptableObject-ассеты), тексты, README, правки по готовому образцу |
| **—** | Без ИИ: творчество детей (концепты, цвета, звуки, голоса, раскладка уровня, плейтест) |

> Правило для детей: ИИ объясняет и помогает, но простые скрипты дети пишут сами. Если ИИ написал код, попросите его объяснить каждую строчку.

**Готово, когда:** как проверить, что шаг закончен. Проверяем кнопкой ▶ Play в Unity.
